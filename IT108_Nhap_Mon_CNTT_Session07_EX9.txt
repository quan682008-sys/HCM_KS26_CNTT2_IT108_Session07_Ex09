Bài 9: So sánh và lựa chọn giải pháp tối ưu cho xử lý log tự động 
Phần 1: Phân tích & Đề xuất đa giải pháp
* Input:
* Thư mục cần quét: /var/logs/
* Từ khóa tìm kiếm: TIMEOUT


* Output:
* Danh sách kết quả gồm: Tên đường dẫn file, Số thứ tự dòng chứa lỗi và nội dung dòng log chứa lỗi
* Format mẫu mong muốn: [Đường_dẫn_file]:[Số_dòng]: [Nội_dung_dòng_log].


*  Đề xuất 2 giải pháp:
* Giải pháp 1: (findstr - Tiện ích tích hợp CMD/Windows): Dùng công cụ dòng lệnh native findstr của Windows với cờ đệ quy (/S), cờ in số dòng (/N) và cờ không phân biệt hoa thường (/I).
* Giải pháp 2:  (PowerShell kết hợp Get-ChildItem + Try/Catch): Duyệt từng file log bằng Get-ChildItem, dùng -ErrorAction SilentlyContinue để bỏ qua triệt để các file đang bị tiến trình khác khóa (bẫy dữ liệu).

Phần 3: Triển Khai
Giải pháp chọn: PowerShell (Get-ChildItem + Get-Content + Select-String + try/catch).
Lý do: Xử lý log tự động cần kết quả đủ và không dừng giữa chừng. PowerShell có sẵn LineNumber, kiểm soát lỗi từng file, chạy được đa nền tảng (PowerShell 7+). Chậm hơn findstr một chút nhưng ổn định hơn.
Câu lệnh:
Get-ChildItem "C:\var\logs" -Recurse -File | Select-String "TIMEOUT" | ForEach-Object { "_.Path):_.LineNumber): _.Line.Trim())" }


Xử lý 2 bẫy:
* File bị khóa: Get-Content đọc được file đang được ghi. Nếu vẫn lỗi thì try/catch bỏ qua, cảnh báo và quét tiếp.
* Hoa/thường: Select-String mặc định không phân biệt hoa thường, nên bắt cả TIMEOUT, Timeout, timeout.
Sửa so với bản cũ: thêm -File (bỏ thư mục), và đưa việc bắt lỗi vào đúng bước đọc file (-ErrorAction trên Select-String không có tác dụng với lỗi mở file).
